# นครหินเถ้า · ชุด Sprite ดำ

ชุดภาพเมืองสำหรับตัวละครเกราะดำ `hero-shadow-8dir-v1/male-iron` ตามภาพอ้างอิงที่ผู้ใช้เลือก: สัดส่วนผู้ใหญ่ ลายเส้นวาดละเอียด หินเทา ไม้เก่า เหล็กรมดำ หลังคาชนวน และแสงโคมอำพัน พื้นมีค่าน้ำหนักกลางเพื่อให้เห็นตัวละครชุดดำชัดเจน

- 44 กลุ่มวัตถุ กลุ่มละ 4 ด้าน รวม 176 ภาพ: อาคาร กำแพง ประตู ของตกแต่ง ธรรมชาติ และ NPC 6 อาชีพ
- พื้นถนน หญ้า และสวน 3 แบบ
- PNG ต้นฉบับเป็นภาพโปร่งใส 2 × 2; ไฟล์ใช้งานเป็น lossless WebP 1024 × 1024 และพื้น WebP 512 × 512
- `public/assets/city-sprite-v2/manifest.json` ระบุกรอบภาพ จุดยึด และลำดับทิศจริง ห้ามใช้ลำดับช่องของ PNG โดยตรง เพราะภาพบางกลุ่มเรียงต่างกัน
- เปลี่ยนทิศด้วยภาพแต่ละด้าน วัตถุตั้งตรง ไม่หมุน bitmap ให้เอียง

สร้างด้วย built-in OpenAI image generation โดยใช้ `black-hero-style-reference.png` เป็นภาพอ้างอิงหลัก และ `cottage.png` เป็นตัวอย่างวัสดุร่วมกัน เก็บคำสั่งเต็มใน `generation-prompts.json` และแหล่งต้นฉบับใน `generation-receipts.json` ภาพอ้างอิงสีเขียวเก็บไว้เป็นประวัติการเลือกทิศทางก่อนผู้ใช้ยืนยันชุดดำ ไม่ได้ใช้กับงานที่ผลิตตามมา

แก้ทิศซ้ำของหอนาฬิกาและแปลงดอกไม้ด้วย image generation อีกครั้ง โดยเก็บภาพที่ไม่ผ่านเป็น `*-rejected-orientation.png` แปลงดอกไม้ใช้ TL/TR/BR จาก `flowerbed-repair-sheet.png` และภาพด้าน 270° ที่สร้างแยกใน `flowerbed-270.png` มาแทนช่อง BL: crop alpha แล้วลดขนาดคงสัดส่วนให้พอดีกับขนาดภาพ TR จากนั้นวางกลางช่อง BL โดยไม่วาดแก้พิกเซล คำสั่งและแหล่งภาพแยกอยู่ใน `flowerbed-270-generation.json`

ภาพช่างตีเหล็ก NPC ที่สร้างรอบแรกออกมาเป็นอาคาร จึงสร้างใหม่เป็นตัวคนถือค้อน ใช้ภาพตัวละครเกราะดำกับคนเฝ้าคลังเป็น reference และเก็บคำสั่ง/ต้นฉบับไว้ใน `npc-blacksmith-generation.json` ภาพอาคารที่ไม่ผ่านเก็บไว้ใน `npc-blacksmith-rejected-building.png` และไม่ได้ใช้ในเกม

แปลงไฟล์และตรวจขอบด้วย `python meadow-3d/tools/pack-city-sprite-theme.py` จากรากโปรเจกต์ สคริปต์รักษาภาพต้นฉบับ ตรวจ alpha ครบทุกด้าน ตรวจว่าภาพไม่ถูกตัดหรือซ้อนกัน และสร้าง contact sheets ให้ตรวจด้วยตา

ใช้ ID และตำแหน่ง layout เดิม จึงเปิดแบบร่างเดิมในเครื่องมือจัดเมืองได้ การเปลี่ยนภาพไม่ได้เปลี่ยน collision หรือข้อมูลเกมฝั่ง server โดย NPC ชุดนี้เป็นภาพยืน 4 ด้าน ยังไม่มีคลิป idle animation แยกเฟรม

## กำแพง ประตู และแกนวาร์ป · 23 ต.ค. 2026

เปลี่ยนกำแพงเป็นแนวหินเสริมค้ำยัน เปลี่ยนประตูเป็นหอคอยหลังคาชนวน และเพิ่ม `warp-core` คริสตัลฟ้าอมเขียว 4 ด้าน สร้างด้วย built-in OpenAI image generation: คำสั่งเต็มและไฟล์ต้นฉบับอยู่ใน `fortification-generation.json` กับ `gate-side-generation.json` ภาพก่อนเปลี่ยนเก็บเป็น `wall-before-fortification.png` และ `gate-before-fortification.png`

`python meadow-3d/tools/normalize-city-fortifications.py` ตัดและจัดภาพที่สร้างใหม่ลงช่องโดยรักษา alpha และสัดส่วน ไม่วาดทับภาพ จากนั้นรันตัว pack เดิม สคริปต์เก็บจุดฐานสองปลายของแต่ละด้านใน `fortification-calibration.json` ตัว renderer จับฐานแผงกำแพงให้ตรงกับแกนพื้นเมือง ทำให้กำแพงต่อกันโดยไม่เกิดขั้นในแกนเหนือ–ใต้ ส่วนประตูใช้การขยายเท่ากันทั้งสองแกนและไม่เฉือนภาพ เพราะการบังคับจุดฐานทั้งสองให้ตรงกำแพงทำให้หลังคาและหอคอยผิดสัดส่วน ใช้ฐานหอคอยซ้อนปลายกำแพงเพื่อรับความต่างเล็กน้อยของมุมภาพ โดยจุดกึ่งกลางประตูยังอยู่ที่พิกัด Layout เดิม

เมืองต้นฉบับเพิ่มแกนวาร์ป 4 ชิ้นไว้ด้านในทางออกให้พ้นแนวบังของหอประตู คลัง Layout ใช้ ID `theme:warp-core:3.4` ย้ายและเลือกทิศได้เหมือนวัตถุอื่น เป็นงานภาพและจัดวาง ใช้เส้นทางออกเดิมและไม่เปลี่ยนเงื่อนไขวาร์ปหรือการตัดสินผลฝั่ง server แบบร่างที่มีอยู่จะไม่ถูกเพิ่มชิ้นส่วนอัตโนมัติทุกครั้งที่โหลด

## แก้สัดส่วนประตูด้านข้าง · 24 ต.ค. 2026

ด้านข้างหน้า/หลังใช้ `gate-side-front-v2.png` และ `gate-side-rear-v2.png` สร้างด้วย built-in imagegen จากภาพโครงที่ฉายด้วยสูตรกล้องจริงใน `outputs/gate-camera-guide.html` เพื่อรักษาแนววางที่ผู้ใช้ยืนยัน โดยให้หอคอยและหลังคามีสัดส่วนธรรมชาติ คำสั่งและที่มาบันทึกใน `gate-side-v2-generation.json` จุดต่อกำแพงวัดภายในฐานหินของแต่ละหอคอยและตรวจว่าขนานกับแกนเมืองก่อนวาด ตัว renderer ยังคงใช้ scale เท่ากันสองแกนและไม่เฉือนภาพประตู การเปลี่ยนภาพใช้ ID เดิม จึงไม่เปลี่ยนข้อมูล Layout ที่ผู้ใช้จัดไว้
